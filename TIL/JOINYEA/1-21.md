# 📘 TIL – Git 브랜치 병합 & Rebase 트러블슈팅

## 💡 오늘 배운 것

- `feat` 브랜치는 **dev의 최신 커밋을 rebase로 가져오는 것이 기본 전략**
  - `git pull --rebase origin dev`
- 로컬 브랜치가 꼬였을 경우  
  → **원격 `origin/dev` 기준으로 다시 맞추는 것이 가장 안전함**
- `non-fast-forward` 에러는  
  → **원격 브랜치에 내 로컬에 없는 커밋이 존재한다는 의미**

---

## 🔥 Rebase 중 충돌 관련 포인트

- rebase는 **내 커밋을 하나씩 다시 적용하는 과정**
- 내가 수정하지 않은 파일(프론트 파일 포함)도 충돌이 발생할 수 있음
- 의미 없는 커밋이나 내 작업이 아닌 파일 충돌 시  
  → `git rebase --skip` 으로 해당 커밋 건너뛰기
- rebase가 끝나지 않은 상태에서는
  - `MERGE_HEAD exists`
  - `cannot pull with rebase`
  와 같은 에러가 발생함

  - commit
  - stash
