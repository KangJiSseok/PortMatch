# TIL — 채용 공고 크롤링 파이프라인 기획

## 1. 💡 오늘 새롭게 배운 것 (Learning)

### 개념 설명
채용 공고 서비스를 만들기 위해서는 단순 크롤링이 아니라  
**수집 → 정규화 → 저장 → 갱신**으로 이어지는 파이프라인 설계가 필요하다는 것을 배웠다.

### 핵심 포인트
- 크롤러(워커)와 API 서버는 역할을 분리한다.
- 공고 데이터는 사이트마다 형식이 달라 **정규화 설계가 핵심**이다.
- 추천/검색을 위해서는 “많은 데이터”보다 **일관된 구조의 데이터**가 더 중요하다.

---

## 2. 🚀 문제 해결 기록 (Trouble Shooting)

### 문제 상황
아직 개발 전 단계라, 구현 자체보다  
“어디까지 해야 MVP인가”의 범위가 모호했다.

### 가설 설정
처음부터 완벽한 크롤링과 추천 기능을 목표로 하면  
프로젝트 범위가 과도하게 커질 것이라 생각했다.

### 해결 방법
MVP 기준으로 아래 기능만 우선 구현하기로 범위를 정리했다.

- 주기적 공고 수집
- 기본 필드 중심의 데이터 정규화
- 단순 조건 기반의 공고 추천

### 결과 및 교훈
기술 구현보다 먼저  
**역할과 책임, 범위를 명확히 나누는 것이 중요**하다는 것을 느꼈다.
