# 📝 [TIL] 2026-01-22: Spring Boot 공고 등록 API와 트러블슈팅

오늘은 채용 공고(Job Posting)와 기술 스택(Tech Stack)을 연동하는 API를 개발하며, 백엔드 개발 과정에서 겪을 수 있는 보안 및 데이터 정합성 이슈를 해결했다.

## 1. 구현 기능: 다대다(N:M) 관계 매핑
- **구조:** `JobPosting` (공고) ↔ `PostingStack` (중간 테이블) ↔ `TechStack` (기술 스택)
- **핵심 로직:**
  - `JobPostingDto`에 `List<Long> stackIds`를 포함하여 요청.
  - 서비스 계층에서 공고를 먼저 저장한 후, 반복문을 통해 중간 테이블에 스택 정보를 매핑하여 저장.

## 2. 주요 트러블슈팅

### 🚨 Issue 1: HTTP 401 Unauthorized
- **현상:** Curl로 API 요청 시 인증 에러 발생.
- **원인:** Spring Security 설정에서 새로 만든 API 경로(`/api/job-postings/**`)가 화이트리스트(`permitAll`)에 등록되지 않음.
- **해결:** `SecurityConfig.java`의 인가 정책에 해당 경로를 추가하여 해결.



### 🚨 Issue 2: RuntimeException (기업 ID 부재)
- **현상:** 기업 ID(`cid`)를 찾을 수 없다는 에러와 함께 500 에러 발생.
- **원인:** 데이터베이스의 외래 키(FK) 제약 조건 및 정합성 문제. 상위 데이터인 `User`와 `Company`가 DB에 존재하지 않는 상태에서 `JobPosting`을 저장하려 함.
- **해결:** 1. 테스트용 `User` 생성 (Role: COMPANY).
  2. 생성된 사용자와 연결된 `Company` 데이터 INSERT.
  3. DB 툴에서 **Commit** 여부를 확인하여 데이터 반영 확정.

## 3. 오늘의 핵심 코드 정리

### 서비스 계층 (JobPostingServiceImpl)
```java
@Override
@Transactional
public void saveJobPostingWithStacks(JobPostingDto dto) {
    // 1. 공고 정보 저장
    saveJobPosting(dto);
    
    // 2. 스택 연결 (중간 테이블 활용)
    if (dto.getStackIds() != null) {
        for (Long sId : dto.getStackIds()) {
            TechStackEntity techStack = techStackRepository.findById(sId)
                    .orElseThrow(() -> new RuntimeException("존재하지 않는 스택 ID"));
            
            postingStackRepository.save(PostingStackEntity.builder()
                    .jobPosting(jobPosting)
                    .techStack(techStack)
                    .build());
        }
    }
}
