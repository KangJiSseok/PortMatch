# 📝 [TIL] 2026-01-24: JPA 쿼리 메서드를 활용한 공고 검색 및 필터링 기능 확장

오늘은 기존의 단순 CRUD를 넘어, 사용자가 원하는 조건(기업별, 제목 키워드별)으로 공고를 필터링하고 검색할 수 있는 기능을 구현했다.

## 1. 구현 기능: 조건별 상세 조회 및 검색
- **구조:** 클라이언트 요청 ➡️ Controller (파라미터 수신) ➡️ Service (비즈니스 로직) ➡️ Repository (JPA 쿼리 실행)
- **핵심 로직:**
  - **기업별 조회:** 특정 기업의 고유 식별자(`cid`)를 기준으로 해당 기업이 등록한 모든 공고를 리스트업.
  - **제목 키워드 검색:** SQL의 `LIKE %keyword%`를 활용하여 제목에 특정 단어가 포함된 공고를 모두 조회.

## 2. 주요 트러블슈팅

### 🚨 Issue 1: PropertyReferenceException (엔티티 필드 탐색 오류)
- **현상:** 프로젝트 실행 시 `No property 'id' found for type 'Company'` 에러 발생.
- **원인:** `JobPostingRepository`에서 `findByCompanyId`로 메서드 이름을 지었으나, 실제 연관된 `Company` 엔티티의 PK 필드명은 `cid`였음.
- **해결:** JPA의 명명 규칙에 따라 메서드 이름을 `findByCompanyCid`로 수정하여 필드 경로를 정확히 일치시킴.

### 🚨 Issue 2: 파라미터 타입 불일치 (Long vs String)
- **현상:** 서비스 계층에서 파라미터를 넘길 때 타입 미스매치 에러 발생.
- **원인:** 기업 식별자(`cid`)를 `Long`으로 처리하려 했으나, 실제 DB와 엔티티에서는 `String` 타입을 사용 중이었음.
- **해결:** 컨트롤러부터 레포지토리까지 `cid` 관련 파라미터 타입을 `String`으로 통일하여 해결.

## 3. 오늘의 핵심 코드 정리

### 레포지토리 계층 (JobPostingRepository)
```java
@Repository
public interface JobPostingRepository extends JpaRepository<JobPostingEntity, String> {
    // 1. 기업 식별자(cid)로 공고 리스트 조회
    List<JobPostingEntity> findByCompanyCid(String cid);

    // 2. 제목에 키워드가 포함된 공고 조회 (LIKE 검색)
    List<JobPostingEntity> findByTitleContaining(String keyword);
}
@Override
public List<JobPostingDto> getJobsByCompany(String cid) {
    // 특정 기업의 공고를 가져와 DTO 리스트로 변환
    return jobPostingRepository.findByCompanyCid(cid).stream()
            .map(this::convertToDto)
            .toList();
}

@Override
public List<JobPostingDto> getJobsByTitleKeyword(String keyword) {
    // 제목 키워드 포함 공고 검색
    return jobPostingRepository.findByTitleContaining(keyword).stream()
            .map(this::convertToDto)
            .toList();
}
