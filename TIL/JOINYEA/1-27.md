# 📝 [TIL] 2026-01-27: Docker 네트워크와 OpenVidu WebRTC 연동 트러블슈팅

오늘은 Spring Boot 백엔드에서 OpenVidu 서버로 세션 생성 API를 호출할 때 발생한 연결 오류를 해결했다. Docker 컨테이너 간 네트워크 설정 문제였으며, `extra_hosts` 제거와 Nginx 프록시 설정을 통해 WebRTC 통신 구조를 완성했다.

## 1. 구현 기능: OpenVidu 화상 면접 세션 관리
- **구조:** `Frontend (Nginx)` ↔ `Backend (Spring Boot)` ↔ `OpenVidu Server`
- **핵심 로직:**
  - 백엔드에서 OpenVidu REST API를 호출하여 세션 생성 및 토큰 발급
  - 클라이언트는 발급받은 토큰으로 WebSocket(WSS) 연결하여 WebRTC 통신
  - Nginx가 `/openvidu` 경로를 OpenVidu 서버로 프록시

## 2. 주요 트러블슈팅

### 🚨 Issue 1: Docker 네트워크 DNS 해석 오류
- **현상:** 백엔드에서 `http://openvidu-server:4443` 호출 시 `Connection refused` 발생
- **원인:** `docker-compose.yml`에 `extra_hosts: - "openvidu-server:host-gateway"` 설정으로 인해 `openvidu-server`가 `172.17.0.1` (잘못된 IP)로 해석됨
- **해결:** 
  - `extra_hosts` 섹션 완전 제거
  - Docker 내부 DNS가 자동으로 올바른 IP(`172.19.0.9`)를 찾도록 함
  - 백엔드 컨테이너 재생성으로 설정 적용

### 🚨 Issue 2: WebRTC HTTPS 요구사항 미충족
- **현상:** 클라이언트가 `wss://i14d205.p.ssafy.io/openvidu`로 연결해야 하는데 Nginx에 프록시 설정 없음
- **원인:** WebRTC는 보안상 HTTPS/WSS 환경에서만 작동하지만, Nginx에 OpenVidu WebSocket 프록시 미설정
- **해결:** Nginx `default.conf`에 `/openvidu` location 블록 추가하여 SSL 종료 후 내부 HTTP로 프록시

### 🚨 Issue 3: 컨테이너 재생성 시 설정 초기화
- **현상:** 서버에서 직접 수정한 Nginx 설정이 컨테이너 재시작 시 사라짐
- **원인:** Docker 이미지에 포함된 설정 파일이 런타임 수정을 덮어씀
- **해결:** Git 저장소의 `nginx/default.conf` 파일을 수정하고 commit/push하여 영구 적용

## 3. 오늘의 핵심 설정 정리

### Docker Compose 수정 (docker-compose.prod.yml)
```yaml
backend:
  environment:
    - OPENVIDU_URL=http://openvidu-server:4443  # Docker 내부 네트워크 사용
    - OPENVIDU_SECRET=MY_SECRET
  # extra_hosts 제거 - Docker DNS가 자동으로 IP 해석하도록 함
```

### Nginx 프록시 설정 (nginx/default.conf)
```nginx
server {
    listen 443 ssl http2;
    server_name i14d205.p.ssafy.io;
    
    # 백엔드 API 프록시
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
    }
    
    # OpenVidu WebSocket 프록시 (추가)
    location /openvidu {
        proxy_pass http://openvidu-server:4443;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;      # WebSocket 업그레이드
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400;                     # 24시간 타임아웃
    }
}
```

### 연결 테스트 및 확인
```bash
# 1. 백엔드 → OpenVidu 내부 연결 확인
docker exec portmatch-backend-prod sh -c "curl -v http://openvidu-server:4443"
# → Connected to openvidu-server (172.19.0.9) ✅

# 2. OpenVidu API 세션 생성 테스트
docker exec portmatch-backend-prod sh -c "curl -u OPENVIDUAPP:MY_SECRET \
  -X POST http://openvidu-server:4443/openvidu/api/sessions \
  -H 'Content-Type: application/json' -d '{}'"
# → {"id":"ses_Svc8D4kL3T",...} ✅

# 3. 외부 API 엔드포인트 테스트
curl -X POST 'http://i14d205.p.ssafy.io:8102/api/interview/sessions'
# → 세션 ID 및 토큰 반환 ✅
```

## 4. 배운 점

### Docker 네트워크 이해
- **Docker 내부 통신**: 같은 네트워크의 컨테이너끼리는 서비스 이름으로 직접 통신 가능
- **extra_hosts 주의**: 호스트 IP를 강제 매핑하면 Docker DNS를 우회하여 오류 발생 가능
- **네트워크 확인**: `docker network inspect <네트워크명>`으로 실제 IP 확인 필수

### WebRTC 통신 구조
- **이중 통신 경로**:
  - 백엔드 ↔ OpenVidu: HTTP 내부 통신 (세션/토큰 관리)
  - 클라이언트 ↔ OpenVidu: HTTPS/WSS 외부 통신 (미디어 스트림)
- **HTTPS 필수**: WebRTC는 보안상 HTTPS 환경에서만 카메라/마이크 접근 허용
- **Nginx 역할**: SSL 종료(termination) 후 백엔드로 HTTP 프록시

### 인프라 설정 관리
- **IaC(Infrastructure as Code)**: 설정 파일은 Git으로 관리하여 버전 관리 및 재현 가능성 확보
- **컨테이너 불변성**: 런타임 수정은 임시방편, 영구 적용은 이미지 레벨에서 처리
- **재배포 전략**: 설정 변경 시 `docker compose up -d --force-recreate` 또는 이미지 재빌드
