## 데이터 파이프라인 자동화: 크롤링 데이터 적재 및 API 연쇄 호출 최적화

크롤링한 데이터를 DB에 적재하는 것에 그치지 않고, Spring Boot 서버와의 API 연동을 통해 **AI 분석 및 임베딩 생성**까지 이어지는 전 과정을 자동화하고 정합성을 검증했다.

---

## 1. 구현 내용: Python-Spring 연쇄 파이프라인 구축
### 데이터 흐름 및 자동화
- **API 연쇄 호출(Chaining)**: Python 적재 스크립트에서 Spring의 분석 API(`Analysis`) 호출 성공 시, DB에서 생성된 ID를 즉시 조회하여 임베딩 API(`Embedding`)까지 자동으로 요청하도록 구현.
- **데이터 정합성 유지**: `conn.commit()`의 위치를 조정하여 회사 정보가 DB에 물리적으로 저장된 후 API 요청이 가도록 순서를 보장함.

### 핵심 성과
- **적재 효율성**: `check_company_project_exists` 로직을 통해 이미 분석된 회사는 건너뛰어 불필요한 AI 연산 비용과 시간을 절약함.
- **운영 편의성**: JSON 전처리 데이터를 DB로 옮기는 과정에서 API 응답 결과(저장된 임베딩 개수 등)를 실시간 로그로 출력하여 가시성 확보.

## 2. 주요 트러블슈팅

### 🚨 Issue 1. 신규 데이터와 기존 데이터의 임베딩 불일치
- **현상**: 전체 회사는 10곳인데 임베딩 데이터는 3개만 생성되는 현상 발생.
- **원인**: 기존에 분석(Analysis)만 완료된 데이터가 있는 상태에서, "분석 결과가 있으면 패스"하는 로직 때문에 이후 단계인 임베딩 요청이 누락됨.
- **해결**: 
  - **단기**: DB를 `TRUNCATE CASCADE`로 초기화한 후 처음부터 다시 적재하여 데이터 정합성 100% 맞춤.
  - **장기**: "분석은 있지만 임베딩이 없는 경우"를 체크하는 `check_embedding_exists` 로직 추가 고려.

---

### 🚨 Issue 2. API 호출 시점의 데이터 참조 에러
- **현상**: Spring API에서 분석 대상 회사를 찾지 못하거나 외래 키 제약 조건 에러 발생 가능성 확인.
- **원인**: Python 스크립트의 트랜잭션이 완료(Commit)되기 전에 외부 API가 DB를 참조하려 할 때 발생하는 격리 수준 문제.
- **해결**: 회사 `INSERT` 직후와 API 호출 성공 직후에 명시적으로 `conn.commit()`을 수행하여 Spring 서버가 최신 데이터를 읽을 수 있게 보장함.

## 3. 핵심 개념 정리

### 멱등성(Idempotency)과 데이터 적재
똑같은 스크립트를 여러 번 실행해도 결과가 같아야 한다. 이미 존재하는 데이터는 건너뛰고(`Skip`), 누락된 데이터만 채워 넣는 로직을 짜는 것이 안정적인 파이프라인의 핵심이다.

### API 연쇄 호출 시의 비동기 vs 동기
- **동기(Sync)**: 현재 방식. 분석이 끝날 때까지 기다렸다가 임베딩을 요청하므로 구현이 직관적이고 순서가 보장됨.
- **비동기(Async)**: 데이터가 많아질 경우 Spring 내부에서 `Event`나 `Message Queue`를 사용하여 "분석 완료 시 자동으로 임베딩 시작"하도록 설계하는 것이 유리함.

### DB 초기화와 TRUNCATE CASCADE
외래 키(FK)로 복잡하게 얽힌 테이블을 비울 때는 자식 테이블부터 지우거나 `CASCADE` 옵션을 사용하여 참조 무결성을 깨뜨리지 않고 초기화하는 것이 중요하다.
