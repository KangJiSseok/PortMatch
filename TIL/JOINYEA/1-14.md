## 💡 오늘 새롭게 배운 것 (TIL)

> Git에서 브랜치를 합칠 때 사용하는 병합 전략에 대해 학습했다.
> 
- 1️⃣ **Merge (기본 merge)**
    - `merge commit`을 새로 생성
    - 브랜치의 흔적이 그대로 남음
    - **장점:** 작업 흐름이 명확
    - **단점:** 히스토리가 복잡해질 수 있음
    
    ```
    main ──●────●
            ╲    ╲
    feature  ●────●
                ↑mergecommit
    
    ```
    
    2️⃣ **Rebase (내가 헷갈렸던 그거!)**
    
    - 내 브랜치의 커밋을 **기준 브랜치 위로 다시 쌓음**
    - merge commit이 생기지 않음
    - **장점:** 히스토리가 한 줄로 깔끔
    - **단점:** 이미 공유된 브랜치에 쓰면 위험 ⚠️
    
    ```
    main     ──●────●
    feature        ●──●   (기준 위로 재배치)
    
    ```
    
    👉 *“기록을 바꾸는 방식”이라 조심해서 써야 한다는 점이 핵심*
    
    3️⃣ **Squash Merge**
    
    - 여러 커밋을 **하나의 커밋으로 압축해서 병합**
    - **장점:** 결과만 남겨서 깔끔
    - **단점:** 작업 과정이 히스토리에서 사라짐
    
    ```
    feature: ● ● ●  →  ● (하나로 합쳐짐)
    
    ```
    
- **정리 한 줄**
    
    > Merge = 기록 보존
    > 
    > 
    > Rebase = 기록 정리
    > 
    > Squash = 결과만 남김
    >
