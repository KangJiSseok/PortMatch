# 📘 TIL – 채용 공고 도메인 설계 & JPA 이해

## 💡 오늘 배운 것
- 채용 공고 서비스를 만들기 위해 **ERD를 기반으로 DB 테이블 구조를 설계**했다.
- 공고, 기업, 기술 스택을 각각 분리하여 **정규화된 테이블 구조**로 구성했다.
- 공고와 기술 스택은 **N:M 관계**이므로 중간 매핑 테이블(`posting_stack`)이 필요하다는 것을 이해했다.
- 공고 상세 내용처럼 길어질 수 있는 데이터는 `VARCHAR`보다 **`TEXT` 타입이 적합**하다는 것을 알게 되었다.
- `JpaRepository<Entity, ID>`를 상속하면 기본적인 **CRUD 기능을 자동으로 제공**받을 수 있다.

## 🧐 헷갈렸던 점 정리
- ERD에서 표현한 관계가 실제 DB에서는 **외래키(FK)와 복합 기본키(PK)** 로 구현된다는 점이 처음에는 헷갈렸다.
- Repository는 직접 구현하는 클래스가 아니라 **인터페이스이며**, 실제 구현체는 Spring이 자동으로 생성한다는 점을 다시 정리했다.

## ✍️ 한 줄 정리
> 채용 공고 도메인을 기준으로 ERD → SQL → JPA까지 이어지는 전체 설계 흐름을 이해했다.
