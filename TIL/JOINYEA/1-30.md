# 📝 [TIL] 2026-01-30
## OpenVidu v2 WebRTC 인프라 구축 및 웹소켓 경로 최적화

실제 배포 환경(Nginx + Docker)에서 발생하는 **WebRTC 연결 에러(401/404)**를 해결하기 위해, 백엔드 토큰 생성 로직과 Nginx 리버스 프록시 설정을 최적화했다.

---

## 1. 구현 내용: Production 환경용 토큰 정제 로직  
### 데이터 흐름 최적화

OpenVidu 내부 주소(ws://...:4443)를 외부 정문 주소(wss://.../openvidu)로 치환.

프론트엔드 SDK 호환성을 위해 **순수 토큰 값(tok_...)**만 추출하여 전달하도록 변경.

### 핵심 성과

SSL 환경(HTTPS)에서의 혼합 콘텐츠(Mixed Content) 차단 문제 해결.

프론트엔드 라이브러리(SDK)의 자동 경로 인식 기능 최적화.

---

## 2. 주요 트러블슈팅  

### 🚨 Issue 1. 웹소켓 인증 실패 (401 Unauthorized)

현상 - 프론트에서 session.connect(token) 시도 시 401 에러 발생.

원인 - 백엔드에서 생성한 토큰 주소에 포함된 도메인/포트 정보가 프론트의 실제 접속 주소와 불일치.

SDK가 전체 URL 형태의 토큰 문자열을 잘못 파싱함.

해결 - 백엔드에서 originalToken.split("token=")[1] 로직을 통해 순수 토큰 값만 추출.

프론트엔드에 JSON 객체가 아닌 String으로 직접 응답하여 기존 코드와의 호환성 확보.

---

### 🚨 Issue 2. 경로 탐색 실패 (404 Not Found)

현상 - 토큰값은 정상적으로 받아오나, 웹소켓 핸드셰이크 과정에서 404 응답.

원인 - Nginx 경로 설정 미비: /openvidu 요청을 오픈비두 컨테이너로 보낼 때 경로 치환(/) 누락.

SDK 기본값 충돌: 순수 토큰만 넣었을 때 SDK가 /openvidu 경로를 찾지 못함.

해결 - Nginx 수정: proxy_pass http://openvidu-server:4443/; (끝에 / 추가로 경로 매핑 해결).

Frontend 수정: OV.setAdvancedConfiguration({ httpUri: "https://.../openvidu" }) 설정으로 명시적 경로 지정.

## 3. 핵심 개념 정리  

### 왜 백엔드에서 주소를 정제해야 할까?
인프라 환경(Nginx, SSL)이 복잡해질수록 내부 서버 주소와 외부 노출 주소가 달라지기 때문이다.

### SSL/TLS 통일성

서비스가 HTTPS(443)라면 웹소켓도 반드시 WSS여야 하며, 이를 백엔드에서 명시해줘야 브라우저 보안 정책을 통과한다.

### Reverse Proxy의 역할

사용자는 하나의 도메인으로 들어오지만, Nginx는 이를 /api(백엔드), /openvidu(WebRTC) 등으로 분기 처리한다.

### 보안 캡슐화

프론트엔드가 서버의 내부 포트(4443, 5443 등)를 알 필요 없이, 약속된 '정문' 주소만 사용하게 함으로써 인프라 보안을 강화한다.
