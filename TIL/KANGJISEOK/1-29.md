# TIL: Git Rebase 중 실수로 모든 커밋을 덮어씌웠지만, reflog로 복구할 수 있었던 경험

## 상황 요약
git rebase 도중 충돌이 발생했다.
충돌을 해결하면서 잘못된 코드 상태를 기준으로 해결해버렸고,
그 상태로 git rebase --continue를 반복했다.

### 그 결과

- 모든 커밋에 같은 잘못된 코드가 덮어씌워짐
- rebase가 끝난 뒤
    - 커밋 해시가 전부 새로 생성됨

이후 아무 의심 없이
```
git push --force-with-lease
```

를 실행

### 결과적으로:

❌ 원격 브랜치에도 잘못된 히스토리가 덮어씌워짐

❌ 로컬 브랜치도 동일한 상태

❌ 기존의 “정상 코드”가 사라진 것처럼 보이는 상황

이때 처음 든 생각은:

“아… 이거 진짜 날렸다. 초 비상”

## 왜 되돌릴 수 없다고 느꼈을까?

- git log 기준으로는 정상 코드였던 커밋이 보이지 않음
- rebase + force push로 기존 커밋 해시는 브랜치에서 완전히 사라진 것처럼 보임
- 브랜치를 기준으로 보면 과거로 돌아갈 포인트가 없음


## git reflog
컨설턴트님이 사용하신 명령어는 이것이었다.

```
git reflog
```

### git reflog가 보여주는 것

git reflog는 다음을 기록한다.

- HEAD가 어떤 커밋을 거쳐 이동했는지
- rebase, reset, checkout, merge, commit
- 심지어 강제 push 이전 상태까지

즉 

- 브랜치에서 떨어져 나간 커밋
- rebase 중 생성됐다가 버려진 커밋
- reset으로 사라진 커밋
