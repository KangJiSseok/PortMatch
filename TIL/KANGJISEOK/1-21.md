
# TIL — Docker 이미지 vs Git Clone 배포, 그리고 용량의 진실

### 1️⃣ Spring Boot JAR를 Docker 이미지로 만들면 용량은 줄어들까?

결론부터 말하면 그대로 만들면 커지고, 잘 만들면 거의 그대로이거나 더 작아질 수도 있다.

Spring Boot JAR: 약 100MB

아무 생각 없이 Docker 이미지화:

openjdk:17 기반

결과 이미지: 400~500MB

이유:

Linux OS

JVM(JDK)

애플리케이션 JAR
→ 실행에 필요한 모든 것이 포함되기 때문

최적화하면?

distroless / JRE 기반 이미지

멀티 스테이지 빌드

Spring Boot Layered JAR 사용

👉 최적화 시: 120~150MB 수준까지 가능

### 2️⃣ EC2에서 git clone vs DockerHub 이미지 pull
뭐가 더 빠를까?
🔹 git clone 방식
git clone
→ 의존성 설치
→ gradle/maven build
→ java -jar


소요 시간: 1~5분

단점:

서버마다 빌드 환경 필요

빌드 실패 리스크

스케일 아웃 시 반복 작업

🔹 Docker 이미지 pull 방식
docker pull
→ docker run


소요 시간:

최초 pull: 10~30초

캐시 재사용 시: 1~3초

장점:

빌드 과정 없음

실행 환경 완전 동일

롤백, 배포 자동화 쉬움

👉 운영 환경에서는 Docker pull이 압도적으로 유리

### 3️⃣ “그럼 최초 1회는 git clone이 더 빠르지 않나?”

상황에 따라 다르지만,

Spring Boot + 의존성 많은 프로젝트

이미지 150MB 이하

👉 대부분 Docker pull이 더 빠름

### 4️⃣ Git Repository 크기와 Docker Image 크기는 같을까?

❌ 전혀 다르다.

- Git Repository
- 소스 코드
- 설정 파일
- 커밋 히스토리
- 문서

👉 예: 20~30MB

- Docker Image
- Linux OS
- JVM
- 라이브러리
- 빌드 결과물(JAR)

👉 예: 120~200MB
