# TIL - AI 정확도(성능) 측정 방법 정리

## 📌 배경

포트폴리오 기반 기업 매칭 기능을 개발하면서,  
여러 가지 AI 설계 방법 중 **가장 정확도가 높은 방식**을 선택해야 하는 상황이 발생했다.

비교 대상은 다음과 같았다.

- 임베딩 설계 방식 변경
- 유사도 측정 방식 변경 (cosine similarity 등)
- LangGraph 사용 시
  - 프롬프트 변경
  - 노드 추가 / 삭제 / 구조 변경

문제는 **"어떤 방식이 가장 정확한가?"를 어떻게 객관적으로 측정할 것인가**였다.

이에 대해 코치님께 정확도 측정 방법에 대한 조언을 받았다.

---

## 🎯 목표

> 여러 AI 설계 방식 중 가장 정확도가 높은 방식을 선택하기 위해  
> 체계적인 평가 방법을 마련한다.

---

## 🧪 정확도 측정 전체 흐름

### 1️⃣ 테스트 케이스(Test Case) 작성

먼저 사람이 직접 기준이 되는 테스트 데이터를 만든다.

예시:
- 포트폴리오 A → 추천 기업 X, Y, Z 가 적절한가?
- 포트폴리오 B → 추천 기업 중 실제로 어울리는 기업은 무엇인가?

즉,  
**입력(포트폴리오) + 기대 결과(정답 기업)** 형태의 테스트 세트를 구성한다.

---

### 2️⃣ AI를 이용해 테스트 케이스 확장

사람이 만든 테스트 케이스는 수가 적기 때문에,
LLM을 활용해 테스트 케이스를 자동으로 늘린다.

예:
- 기존 포트폴리오 유형을 변형한 추가 샘플 생성
- 다양한 직무/기술 스택 조합 생성
- 엣지 케이스(애매한 경우) 추가 생성

이렇게 하면:
- 평가 데이터가 많아져 신뢰도가 높아짐
- 특정 케이스에만 맞춰진 모델이 되는 것을 방지할 수 있음

---

### 3️⃣ 결과 평가 방법

#### ✅ 방법 1: 사람이 직접 눈으로 확인 (Human Evaluation)

- AI가 추천한 기업 리스트를 직접 보고
- "이 매칭이 합리적인가?"를 사람이 판단

장점:
- 직관적이고 정확
- 실제 사용자 관점 반영 가능

단점:
- 시간이 많이 듦
- 주관적일 수 있음

---

#### ✅ 방법 2: LLM을 이용한 자동 평가 (LLM as Judge)

중요한 포인트:
> **임베딩에 사용한 모델과 다른 LLM 모델을 사용해서 평가해야 함**

이유:
- 같은 모델을 쓰면 자기 결과를 자기 기준으로 평가하게 되어 편향 발생
- 객관성이 떨어짐

방법:
- GPT, Claude, Gemini 등 여러 모델로 평가
- 프롬프트 예시:
이 포트폴리오와 추천된 기업 목록이 얼마나 적절한지 1~5점으로 평가하고 이유를 설명하라.


이 점수를 통해:
- 각 방식별 평균 점수 비교
- 가장 점수가 높은 설계를 채택

---

## 🔍 비교 대상 예시

실험 대상이 될 수 있는 요소들:

### 🔹 임베딩 설계 방식
- 전체 포트폴리오를 하나로 임베딩
- 프로젝트 단위로 쪼개서 임베딩
- 문제/해결/기술/역할별 분리 임베딩

### 🔹 유사도 측정 방식
- Cosine Similarity
- Euclidean Distance
- Top-K 평균 점수 방식 등

### 🔹 LangGraph 구조
- 프롬프트 변경
- 노드 추가 (요약 노드, 정제 노드 등)
- 불필요한 노드 제거
- 판단 노드 구조 변경

각 케이스를 동일한 테스트 데이터에 적용하여 점수를 비교한다.

---

## 🧠 핵심 정리

- AI 정확도 측정은 **감각이 아니라 실험으로 결정해야 한다**
- 평가 프로세스:
1. 테스트 케이스 작성
2. AI로 테스트 데이터 확장
3. 사람 또는 LLM으로 결과 평가
4. 여러 방식의 점수를 비교
- 평가용 LLM은 반드시 임베딩 모델과 다른 모델을 사용한다
- 이 과정을 통해 가장 신뢰도 높은 설계를 선택할 수 있다

---

## ✨ 느낀 점

- AI 개발은 단순히 "잘 나오는 것 같다"가 아니라
**정량적으로 비교하고 선택하는 과정**이 필요하다는 것을 배웠다.
- 정확도 측정 방법 자체가 하나의 중요한 설계 요소라는 것을 깨달았다.
- 이 방식은 포트폴리오 매칭뿐만 아니라
검색, 추천, 요약 등 모든 AI 기능 평가에 적용 가능하다.

---

## 📎 앞으로 적용 계획

- 임베딩/유사도/프롬프트 설계별 실험 자동화
- LLM 평가 프롬프트 템플릿 제작
- 결과 로그 및 점수 테이블화
