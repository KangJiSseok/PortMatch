# 📒 TIL – Rebase Conflict로 파일이 꼬였고, Reflog로 커밋/코드 복구한 경험

## 🧨 문제 상황

`rebase` 진행 중 conflict가 발생했다.
충돌을 해결하는 과정에서 **내 파일을 반영해야 하는데 원격 변경사항이 반영**되면서 파일이 꼬였다.

그 결과:

* rebase가 계속 진행되면서 **내 작업 파일 내용이 사라진 듯한 상태**가 됨
* `rebase` 특성상 커밋이 재작성되면서, 로그를 보면 **원격 커밋 기록이 덮어써진 것처럼 보여서** “큰일 났다”는 상황이 됨
* 특히 push를 잘못하면 **원격 히스토리를 망가뜨릴 수 있다는 불안**이 크게 옴

---

## 🔎 원인 정리

### 1) Rebase는 “병합”이 아니라 “재작성”이다

`rebase`는 내 커밋을 기준 브랜치 위로 옮기면서 **커밋을 새로 만들어 붙이는 방식**이라서:

* 커밋 해시가 바뀌고
* 히스토리 모양이 달라지고
* 중간에 conflict를 잘못 해결하면 **내 변경이 빠진 채로 다음 커밋들이 계속 얹힐 수 있다**

즉, conflict 해결을 한번 잘못하면 이후가 “겉보기엔 정상”인데 실제론 내용이 꼬인 상태가 된다.

---

### 2) Conflict에서 잘못 반영되면 “파일이 꼬인 채로 rebase가 계속된다”

conflict가 났을 때:

* 원하는 것은 **내 변경사항이 들어간 최종 파일**
* 그런데 실제로는 **원격 쪽 변경(혹은 내 변경이 누락된 버전)이 들어간 파일**로 정리돼버림

이 상태에서 그대로:

```bash
git add .
git rebase --continue
```

를 반복하면, 내 변경이 빠진 상태로 커밋이 계속 만들어져서
**“내 코드가 사라졌는데 커밋은 진행된”** 기묘한 상태가 된다.

---

## 😱 당시 가장 무서웠던 포인트

rebase가 끝난 뒤 `git log`를 보니

* 내 커밋이 안 보이거나
* 히스토리가 이상하게 바뀌어 보이고
* 마치 “원격 커밋 기록이 다 덮인 것 같은” 느낌이 들었다.

하지만 실제로는:

* rebase로 인해 **커밋이 새로 작성되면서 히스토리 형태가 바뀐 것**
* 그리고 conflict 해결 과정에서 파일이 잘못 반영되어 **내용이 꼬인 것**

이 두 가지가 동시에 겹쳐서 “망했다”처럼 보였던 것이다.

---

## 🛟 해결 – `git reflog`로 “살아있는 로컬 기록” 찾아 복구

이때 핵심이 **reflog**였다.

### ✅ reflog가 해준 일

`git log`는 현재 브랜치에서 “살아남은 커밋들”만 보여주지만,
`git reflog`는 **HEAD가 이동했던 이력 자체**를 기록한다.

즉, rebase로 히스토리가 재작성돼서 log에서 사라진 커밋도
reflog에는 남아있을 수 있다.

---

### 1) reflog로 정상 시점 찾기

```bash
git reflog
```

여기서:

* rebase 시작 전
* 또는 파일이 꼬이기 전
* “내 커밋이 확실히 살아있던 시점”

의 커밋 해시를 찾는다.

---

### 2) 해당 시점으로 되돌리기 (복구)

보통 아래처럼 복구했다:

```bash
git reset --hard <복구할 커밋 해시>
```

이렇게 하니:

* 꼬였던 파일이 정상으로 돌아오고
* “사라졌던 내 커밋/작업 내용”도 다시 복구됐다

---

## 📚 배운 점

### 1) Rebase conflict는 “그 순간의 선택”이 전체 결과를 좌우한다

충돌 해결에서 파일이 한 번 잘못 정리되면,
이후 `--continue`로 커밋이 계속 재작성되며 **틀린 결과가 누적**된다.

---

### 2) `git log`에 내 커밋이 안 보인다고 끝난 게 아니다

rebase/reset 등으로 히스토리가 바뀌면
“없어진 것처럼 보이는 커밋”이 생기는데, 그때 **reflog가 진짜 보험**이다.

---

### 3) Panic 나기 전에 체크할 것

* conflict 해결 직후에는 `git diff`, `git status`로 원하는 내용이 맞는지 확인
* rebase가 이상하게 끝났으면 `git reflog` 먼저 확인

---

## 🧠 느낀 점

이번 경험으로 Git을 “명령어”로만 아는 것과
“사고를 복구해본 경험”은 완전히 다르다는 걸 느꼈다.

특히 reflog는 평소엔 안 쓰지만,
진짜 위기 상황에서 커밋과 작업물을 살려주는 **최후의 생명줄**이었다.
