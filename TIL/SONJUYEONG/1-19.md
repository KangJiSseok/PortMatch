# 📝 TIL - Git 기본 흐름 & 브랜치 / stash / 커밋 수정

## 📌 오늘 한 작업 요약

* dev 브랜치 최신화
* 기능 브랜치 생성 및 원격 push
* 변경 사항 관리 (`status → add → commit`)
* pull 오류 원인 이해
* stash를 이용한 작업 임시 저장
* rebase / amend로 커밋 메시지 수정 (push 전)

---

## 1️⃣ 기본 Git 작업 흐름

### 1. dev 브랜치 최신화

```bash
git checkout dev
git pull origin dev
```

* `checkout dev` : 기준 브랜치를 dev로 이동
* `pull origin dev` : 원격 dev 변경 사항을 로컬에 반영

---

### 2. 기능 브랜치 생성

```bash
git checkout -b be-feat/security-config
```

* `-b` 옵션: 브랜치 생성 + 이동
* dev에서 분기한 기능 브랜치에서 작업 시작

---

### 3. 원격 브랜치에 push

```bash
git push -u origin be-feat/security-config
```

* `-u` 옵션: upstream 설정
* 이후부터는 `git push`만으로도 동일 브랜치로 push 가능

---

## 2️⃣ 변경 사항 관리

### 현재 상태 확인

```bash
git status
```

* 수정된 파일
* 새로 생성된 파일
* 스테이징 여부 확인

---

### 스테이징

```bash
git add .
```

* 현재 디렉토리 기준 모든 변경 사항 스테이징

---

### 커밋

```bash
git commit -m "커밋 메시지"
```

예시:

* `feat: company 도메인 생성`
* `fix: user domain 수정`

---

## 3️⃣ pull 오류 원인

### 오류 메시지 예시

```text
cannot pull with rebase: You have unstaged changes
```

### 원인

* 로컬에 커밋되지 않은 변경 사항이 남아 있는 상태에서 pull 수행

### 해결 방법

1. 커밋
2. stash
3. 변경 사항 제거 (`git reset --hard`, 주의)

---

## 4️⃣ stash (작업 임시 저장)

### stash 저장

```bash
git stash
```

* 현재 작업 중인 변경 사항을 임시로 숨김

---

### stash 복원

```bash
git stash pop
```

* 최근 stash를 복원하고 목록에서 제거

---

## 5️⃣ 커밋 메시지 수정 (push 전)

### 최근 커밋 1개 수정

```bash
git commit --amend
```

* 커밋 메시지 또는 내용 수정
* 커밋 해시 변경됨

---

### 여러 커밋 중 특정 커밋 수정

```bash
git rebase -i HEAD~2
```

* `pick` → `reword`로 변경
* 저장 후 메시지 수정

---

## 6️⃣ 오늘의 핵심 정리

* dev에서 직접 작업하지 않는다
* 기능 단위 브랜치를 생성해서 작업한다
* pull 전에 항상 `git status` 확인
* stash는 임시 보관함
* rebase / amend는 push 전에만 안전

---

## ✍️ 느낀 점

Git은 명령어를 외우는 도구가 아니라
작업 흐름과 상태를 관리하는 도구라는 점을 체감했다.
오류를 겪으면서 Git 사용에 대한 이해도가 한 단계 올라갔다.
