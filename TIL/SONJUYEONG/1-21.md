# TIL – Docker 기초 정리 & Spring Security에서 배운 점

## 1. Docker를 왜 쓰는가

Docker는
**“내 로컬 환경과 상관없이 동일한 실행 환경을 보장하기 위한 도구”**이다.

* 개발 환경 차이로 인한 오류를 줄일 수 있음
* DB, Redis 같은 의존 서비스를 쉽게 띄울 수 있음
* 팀 프로젝트에서 환경 설정 공유가 쉬움

---

## 2. Docker 핵심 개념 정리

### 2.1 Image와 Container

* **Image**

  * 애플리케이션 + 실행 명령 + 필요한 파일들이 레이어로 쌓인 설계도
  * 불변(immutable)

* **Container**

  * 이미지를 실제로 실행한 결과물
  * 실행 중인 프로세스 + 파일 시스템 + 네트워크

👉 비유

> Image = 설계도
> Container = 설계도로 지은 실제 집

---

### 2.2 Dockerfile

* **이미지를 만들기 위한 설정 파일**
* 주요 역할

  * 베이스 이미지 지정 (`FROM`)
  * 애플리케이션 복사 (`COPY`)
  * 빌드/실행 명령 정의 (`RUN`, `CMD`, `ENTRYPOINT`)

Dockerfile 하나로
👉 “이 애플리케이션은 이렇게 실행된다”를 명확히 정의할 수 있음

---

### 2.3 Docker Compose

* **여러 컨테이너를 한 번에 관리하는 도구**
* 주 용도

  * Spring 서버 + DB + Redis 등을 한 번에 실행
  * 네트워크, 볼륨, 환경변수 관리

```bash
docker compose up -d --build
```

* `-d` : 백그라운드 실행
* `--build` : 이미지가 바뀌었으면 다시 빌드

---

### 2.4 `.env` 파일의 역할

Docker Compose에서 자주 쓰는 환경 변수 파일

* `.env` 파일이 없으면 컨테이너 실행 실패 가능
* 대안

  * `docker-compose.yml`의 `environment:`에 직접 작성 가능

⚠️ 주의

* `version:` 속성은 최신 Compose(v2)에서는 **필수 아님**
* 경고만 나오고 실행은 정상

## 4. Spring Security와 Docker의 관계

### 4.1 중요한 포인트

* **Spring Security 문제는 Docker 문제가 아니다**
* Docker는

  * 동일한 환경에서 문제를 재현하고
  * 서버 실행을 안정적으로 도와줄 뿐

👉 인증/인가 문제는 **코드와 설정의 영역**

---

## 5. Spring Security에서 배운 핵심 개념들

### 5.1 인증 / 인가 흐름

* **Authentication**

  * “누구인가?”
* **Authorization**

  * “권한이 있는가?”

Spring Security는
👉 **Filter Chain**을 통해 요청을 가로채서 처리한다.

---

### 5.2 401 / 403의 의미

* **401 Unauthorized**

  * 인증 자체가 안 됨
  * 로그인 안 했거나 토큰 없음

* **403 Forbidden**

  * 인증은 됐지만 권한 부족

```java
http.exceptionHandling(ex -> ex
    .authenticationEntryPoint((req, res, e) -> res.sendError(401))
    .accessDeniedHandler((req, res, e) -> res.sendError(403))
);
```

➡️ 이 설정은 **컨트롤러가 아니라 Security 설정 영역**

---

### 5.3 Swagger에서 401이 뜨는 이유

* Swagger는 기본적으로 **인증 정보 없이 요청**
* Spring Security가 요청을 필터 단계에서 차단

👉 해결은 Docker가 아니라:

* Swagger 경로를 `permitAll()` 하거나
* Swagger에 인증 헤더를 설정해야 함

---

### 5.4 `@AuthenticationPrincipal` 이해

```java
@GetMapping("/me")
public ApiResponse<?> me(@AuthenticationPrincipal User user) {
    ...
}
```

* SecurityContext에 저장된 `Principal`을 꺼내주는 애노테이션
* 내부적으로는 `SecurityContextHolder`를 사용

```java
@AuthenticationPrincipal(expression = "user")
User user
```

* `UserDetails` 안에 감싸진 실제 User를 바로 꺼낼 때 사용
* **선택 사항**이며 구조에 따라 사용 여부 결정

---

### 5.5 Authentication 객체 vs @AuthenticationPrincipal

| 방식                              | 특징                 |
| ------------------------------- | ------------------ |
| `Authentication authentication` | 가장 로우 레벨, 타입 체크 필요 |
| `@AuthenticationPrincipal`      | 깔끔, 의도 명확          |
| `SecurityContextHolder`         | 내부 구현 이해용          |

👉 실무/협업에서는 `@AuthenticationPrincipal`이 가독성 좋음

---

## 6. 오늘의 핵심 정리

* Docker는 **환경을 통제하는 도구**
* Spring Security는 **요청 흐름을 통제하는 도구**
* 둘은 직접적인 해결 관계는 없지만,

  * Docker 덕분에 Security 이슈를 안정적으로 테스트 가능
