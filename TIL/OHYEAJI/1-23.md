## TIL — 기업 프로필 조회/수정 페이지 구현 (더미 + localStorage 버전)

---

## 1) 오늘 한 일 요약

### ✅ CompanyProfilePage (조회)

- 기업 프로필 조회 페이지 구현
- 섹션 구성
    - 기업 기본 정보 / 소개 / 연락처 / 프로젝트
- **Quick Menu**로 섹션 이동 + 스크롤 UX
- 우측 버튼 정리 + **“맨 위로 이동” 버튼** 제공
- Hero 영역 정렬 개선 (기업명/로고/버튼 배치 안정화)

### ✅ CompanyProfileEditPage (수정)

- 기업 프로필 수정 페이지 구현
- **유효성 검사 강화**
    - 필수값 누락/형식 오류 시 **빨간 테두리**
    - **해당 입력칸으로 자동 스크롤**
- 저장은 **유효성 통과한 경우에만** 진행
- 프로젝트 **추가/삭제 가능**
    - 프로젝트가 **0개여도 저장 가능**하도록 처리

## 2) UX 디테일 (오늘의 “사용자 배려 폭주” 파트)

### 🧷 이탈 방지 UX

- 수정 중 페이지 이탈 시 confirm 모달 노출
    - `useBlocker` + `beforeunload` 조합
- 의도: “저장 안 하고 나가면… 너… 후회해…” 를 친절하게 알려주기

### 🧭 스크롤/이동 UX

- Quick Menu 클릭 → 해당 섹션으로 스무스하게 이동
- “맨 위로” 버튼으로 긴 페이지에서도 복귀 빠르게

---

## 3) 데이터 처리 방식

### 🧠 localStorage 흐름

- 조회 페이지: `localStorage`에 값 있으면 그걸 우선 사용
- 수정 페이지: 폼 초기값도 `localStorage` 기반
- 저장: 검증 통과 시 `localStorage.setItem(...)`로 반영
    
    → 결과: 페이지 이동해도 데이터가 유지되어 “연동된 느낌”을 살림
    

---

## 4) UI/컴포넌트 정리

- 버튼 컴포넌트는 `src/components/Button/Button.tsx`로 **통일**
- Hero 영역 정렬 개선
    - 텍스트만 위로 뜨는 문제 정리
    - 버튼 위치는 안정적으로 유지되게 수정
        
        → 이런 게 진짜 “완성도”를 만들어줌 (티 안 나지만 티 나는 부분)
        

---

## 5) 오늘 배운 점 / 느낀 점

- 백엔드 없을 때도 “흉내”를 잘 내면 개발이 훨씬 빨라진다
    
    → localStorage는 프론트의 임시 백엔드다…
    
- 유효성 검사는 **보여주기(빨간 테두리)** + **안내(스크롤 이동)** 세트가 체감이 확 올라간다
- 이탈 방지는 `useBlocker`만으로 끝이 아니라, 브라우저 닫기/새로고침까지 막으려면 `beforeunload`가 필요하다
