## 1) 공고 기술스택 API: “뭘 쓰는 게 제일 효율적이냐?”

공고 상세에서 스택을 보여줄 때, 스택을 **하나씩 조회**하면 호출이 너무 많아짐.

- `GET /api/stacks/{id}`
  - 스택 **1개**만 조회
  - 공고에 스택이 5개면 **API 5번 호출** → 불편 + 느려질 가능성 큼
- ✅ `GET /api/stacks/posting/{postingId}`
  - 공고 1개에 연결된 스택을 **리스트로 한 번에** 받음
  - 예: `/api/stacks/posting/1` → `[{stackId:1, stackName:"React"}, ...]`
  - 공고 상세 화면 목적이면 이게 제일 깔끔하고 빠름

**결론**

- 공고 상세에서 스택 보여주기 목적이면
  ✅ `GET /api/stacks/posting/{postingId}`가 “맞는 도구”.

## 2) 공고 상세 API 연결 흐름 정리

### (1) Swagger에서 확인

- 엔드포인트: `GET /api/job-postings/{id}`
- `Try it out → Execute`로 테스트
- 정상 응답 예시 흐름
  - HTTP `200`
  - body: `code: 1000`, `message: success`, `data: {...}`
- 없는 id 요청 시
  - HTTP `400` 등(프로젝트마다 다름)
  - body: `code: 2001`, `data: null` 같은 형태 가능

### (2) 프론트에서 붙이는 흐름

- `JobPostDetailPage`에서 `useEffect`로 `fetchJobPostDetail(jobPostId)` 호출
- 결과에 따라 상태 분기:
  - `loading` → 스켈레톤
  - `error` → 에러 UI
  - `notfound` → 비어있음 UI
  - `success` → 상세 렌더링

### (3) “연결됐는지” 빠른 확인법

- 화면에 회사명/제목/마감일/상세요강이 **실제 값**으로 나오면 거의 확정
- 더 확실히 하려면:
  - DevTools Network에서 `/api/job-postings/{id}` 요청이 **200인지** 확인

## 4) axios 공통 인스턴스(클라이언트) 정리

공통 인스턴스의 목적:

- baseURL/timeout/headers/withCredentials 같은 규칙을 **한 번에 통일**
- API 파일들은 이 인스턴스만 가져다 쓰게 해서 “요청 방식이 섞이는 사고”를 줄임

핵심 포인트:

- 세션 쿠키 로그인이라면 `withCredentials: true`는 거의 필수급

## 5) 스크랩 API 붙이기 + 중요한 스펙 체크

Swagger 기준으로 스크랩 관련 API는 아래로 파악:

- **POST** `/api/scraps` : 스크랩 토글 (있으면 삭제, 없으면 등록)
  - params: `uid`, `pid`
- **GET** `/api/scraps/check` : 특정 공고 스크랩 여부 확인 (true/false)
  - params: `uid`, `pid`
- **GET** `/api/scraps/{uid}` : 내 스크랩 목록 조회

그리고 오늘의 함정:

- `pid`가 `job_001` 같은 문자열이 아니라 **숫자 id(1,2,3)** 로 보였음
  → 프론트에서 문자열로 관리 중이면 **전부 숫자 id로 교체**가 맞음

## 6) 401(Unauthorized) 터진 이유: 세션 쿠키가 요청에 안 실렸다

### 증상

- `GET /api/scraps/check?...`에서 **401**이 계속 발생

### 핵심 원인

- 로그인 세션 기반이면 백엔드가 쿠키(JSESSIONID)로 인증함
- 근데 스크랩 요청에 **Cookie가 안 붙으면** 백엔드는 “너 누구?” 하고 401 때림

### “됐다가 안됐다가” 하는 대표 원인 3종 세트

1. 요청이 섞임

- 어떤 요청은 `/api/...`(Vite proxy 경유)
- 어떤 요청은 `http://백엔드주소/...`(직접 호출)
  → 도메인이 달라져서 **localhost에 저장된 쿠키가 안 붙음**

1. axios 인스턴스가 여러 개고 설정이 다름

- 어떤 인스턴스는 `withCredentials: true` 빠져있음
  → 그 요청만 쿠키 없이 나가서 401

1. 프록시 target이 내가 생각한 백엔드가 아님

- env 로딩 꼬임/포트 실수 등으로
  로그인은 A 서버, 스크랩은 B 서버로 가면 당연히 인증 실패

## 7) 디버깅 체크리스트 (다음에 또 터지면 여기부터 보면 됨)

DevTools Network에서 딱 두 개만 보자.

1. 스크랩 요청(`/api/scraps/check`) 클릭

- Request Headers에
  **`Cookie: JSESSIONID=...`** 가 있는지 확인

1. 로그인 요청(`/api/auth/login`) 클릭

- Response Headers에
  **`Set-Cookie: JSESSIONID=...`** 가 내려오는지 확인

✅ 결론 정리:

- 로그인에서 쿠키를 받았는데(Set-Cookie 있음)
- 스크랩 요청에 쿠키가 안 붙는다(Cookie 없음)
  → 프론트 요청이 **쿠키 안 붙는 루트**로 나가고 있는 거
