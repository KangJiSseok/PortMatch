## 2026-01-16 TIL — Git rebase pull, 문서 파싱 AI, 아키텍처/배포 기초

오늘은 Git에서 **rebase 기반 pull**을 쓰는 방법과, 서비스 아키텍처 설계에서 자주 등장하는 개념들(Docker, 서버 분리, 벡터DB, 인증 방식, S3)을 정리했다. 문서 파싱을 위한 오픈소스도 함께 확인했다.

### 1) Git: `git pull --rebase`와 기본 설정

- `git pull --rebase origin docs`
    - 원격 브랜치 변경사항을 가져올 때 **merge commit을 만들지 않고**, 내 커밋을 최신 커밋 위로 “다시 줄 세워서” 히스토리를 **일직선으로 깔끔하게 유지**하는 방식이다.
- rebase 기반 pull을 기본으로 쓰려면 아래 설정을 사용한다.

```bash
git config --global pull.rebasetrue

```

- rebase 중 충돌이 나면 보통 아래 흐름으로 해결한다.
    - 충돌 해결 → `git add .` → `git rebase --continue`
    - 포기하고 원상복구: `git rebase --abort`

### 3) 아키텍처 설계에서 나온 핵심 질문들

### Docker가 뭐지?

- 서버를 띄우려면 운영체제/라이브러리/실행환경이 맞아야 하는데, Docker는 이를 **컨테이너 이미지**로 묶어서 “어디서든 같은 환경으로 실행”하게 해주는 도구다.
- 즉, “내 컴퓨터에서는 되는데 서버에서는 안 돼요” 같은 상황을 줄이기 위한 환경 표준화에 많이 쓴다.

### 서버를 나눌지, 하나로 할지

- **단일 서버(모놀리식)**: 구조가 단순하고 초기 개발/배포가 빠르다.
- **분리(서비스 분리/마이크로서비스 느낌)**: 확장성과 책임 분리가 좋아질 수 있지만, 운영/배포/통신/로그 관리가 복잡해진다.
- 초기에는 보통 단순하게 시작하고, 필요해지면 분리하는 전략도 고려할 수 있다.

### 4) 벡터 DB(Vector DB)

- 임베딩(벡터)을 저장하고, **유사도 검색(예: cosine similarity)**을 빠르게 수행하는 저장소/시스템이다.
- 활용 예:
    - 문서 검색(RAG), 유사 문서 추천, 질문-답변 검색, 콘텐츠 추천 등

---

### 5) 인증 방식: 세션 기반 vs JWT

- **세션 기반**
    - 서버가 로그인 상태를 세션 저장소에 들고 있는 방식(상태(state) 있음)
    - 브라우저 쿠키로 세션 ID를 주고받는 형태가 흔함
- **JWT 기반**
    - 토큰 자체에 인증 정보를 담아 전달하는 방식(서버는 상대적으로 stateless)
    - API/SPA 구조에서 자주 등장

둘 다 장단점이 있고, 서비스 구조(웹/앱, 서버 구성, 보안 요구사항)에 따라 선택이 달라질 수 있다는 점을 확인했다.

### 6) S3

- 사용자가 업로드한 **문서/이미지 같은 파일을 저장하는 객체 스토리지**로 많이 사용된다.
- 보통 구조는
    - 파일은 S3에 저장
    - 파일 메타데이터(경로, 업로더, 생성일, 상태 등)는 DB에 저장
    - 필요하면 파싱/임베딩 처리 후 벡터 DB에 적재
