## TIL (2026-01-28, Wed) — OpenVidu 기반 화상면접 기능 점검 및 구조 정리

### 1. 오늘 수행한 작업

- **화상면접(WebRTC/OpenVidu) 연동 흐름 점검**
    - OpenVidu 기반 접속 절차(세션/토큰 발급 → join → publish/subscribe)를 기준으로 현재 구현 상태를 확인함.
- **테스트 목적의 페이지 분리 방향 정리**
    - DB 기반 면접 데이터(면접 id 등)가 없는 상황에서도 연결 여부를 검증할 수 있도록, 실사용 페이지와 별도로 **연동 검증용(Test) 페이지 구성** 방향을 확립함.
- **토큰 발급 API 및 연결 실패 원인 추적**
    - 세션 ID를 이용해 토큰을 발급받는 API 호출 흐름을 점검하고, 브라우저 콘솔 오류(401 invalid token, connecting 상태 지속)를 기반으로 병목 지점을 파악함.
- **인프라(포트/네트워크) 영향도 검토**
    - OpenVidu 접근을 위한 필수 포트(5443) 이슈 가능성을 확인하고, 인프라 선행 조치 필요성을 정리함.

---

### 2. 이슈 및 관찰 결과

- **토큰 검증 실패(401) 발생**
    - 토큰 발급/전달 형식 문제 또는 OpenVidu 서버 접근 불가(포트/프록시 설정 등) 가능성을 고려함.
- **연결 상태(connecting)에서 진행되지 않는 현상**
    - publish/subscribe 단계 이전에 연결이 정체되는 현상이 확인되어, 우선적으로 네트워크/토큰 발급 경로부터 정상화가 필요하다고 판단함.
- **실면접 데이터 부재로 인한 검증 제한**
    - DB에 실제 면접 엔터티(면접 id 및 세션 매핑)가 없는 상태에서 실사용 플로우 검증이 어려워, 테스트 전용 플로우로 선행 검증 후 이식하는 전략을 채택함.

---

### 3. 정리한 결론

- **프론트 수정만으로 해결 가능한 영역과 백엔드/인프라 선행 영역을 분리하여 대응해야 함**
    - 특히 OpenVidu 접근 포트가 미개방인 경우, 프론트 단에서 추가 디버깅을 진행해도 효과가 제한적임.
- **연결 검증용(Test) 페이지를 우선 완성한 뒤, 실사용 페이지에 단계적으로 이식하는 접근이 효율적**
    - DB/권한/일정 로직과 분리하여 연결 자체의 성공 여부를 빠르게 판별할 수 있음.

3. **Test 페이지에서 2인 접속 기준 영상 송수신(publish/subscribe) 성공 여부 확인**

### 5. 향후 개선 아이디어(자동 세션 생성)

- 기업/지원자에게 세션 정보(또는 토큰 발급 가능 키)를 자동 제공하는 구조를 검토함.
- 프론트는 면접 id 기준으로 세션 정보를 조회하여 연결만 수행하도록 역할을 단순화할 수 있음.
