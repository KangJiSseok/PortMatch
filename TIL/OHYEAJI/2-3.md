## 1️⃣ (프론트엔드) 마이페이지 기업 스크랩 목록 추가

### 문제

* 사용자가 기업을 스크랩할 수는 있었지만
* 마이페이지에서 이를 확인할 수 있는 화면이 존재하지 않았음

### 해결

* 기업 스크랩 목록 API 연동
* 스크랩 전용 타입 정의
* 마이페이지 UI 레이아웃 수정 후 스크랩 영역 추가

### 결과

* 사용자가 자신의 관심 기업을 한눈에 확인 가능
* 마이페이지가 단순 정보 페이지가 아니라 **사용자 행동의 결과를 보여주는 화면**으로 진화

## 2️⃣ (AI/LLM) 포트폴리오 데이터 추출 및 분석 이슈

### ① 역할(Role) 데이터 누락 (Extraction Failure)

**증상**

* PDF에 *My Role & Contribution* 섹션이 존재했음에도
* 분석 결과 JSON에서 `role: null` 반환
* "담당 역할이 명시되지 않았습니다"라는 잘못된 피드백 생성

**원인**

* 2단 레이아웃(텍스트 + 이미지) 구조에서
  LLM이 특정 헤더 영역을 인식하지 못하고 건너뜀

**해결**

* 프롬프트 개선

  * `Role`, `Contribution`, `담당` 키워드 주변 텍스트를 **최우선 탐색**하도록 수정
* 이후 정상 추출 확인

---

### ② 기술 스택 과잉 추출 (Hallucination)

**증상**

* 실제 사용 기술은 `Milvus`였으나
* 본문 설명에 등장한 `Pinecone`까지 기술 스택으로 포함됨

**원인**

* Tech Stack 섹션뿐 아니라
  본문 설명 텍스트까지 추출 대상으로 포함

**개선 방향**

* 프롬프트에 제약 조건 추가 필요

  * "기술 스택은 반드시 Tech Stack 리스트에 명시된 항목만 추출"

---

### ③ 성과(Metrics) 인식 판단

**상황**

* "기여도 40%"라는 문구가 있었으나 `metrics: null` 반환

**해석**

* 단순 기여도는 정량적 성과 지표로 보기 어려움
* LLM이 이를 무시하고
  "정량적 성과가 명확하지 않다"고 판단한 것은 정상 동작으로 판단

## 4️⃣ (백엔드) PeerJS 커스텀 시그널링 서버 구현

### 배경

* PeerJS는 P2P 연결은 쉽게 제공하지만
  "누가 누구와 언제 연결해야 하는지"는 직접 관리해야 함
* 면접 예약 시간과 방(Room) 개념이 필요한 프로젝트 특성상
  Spring Boot + RDB 기반의 **커스텀 시그널링 서버**를 구현함

---

### 핵심 설계

#### 시그널링 흐름 (Polling 방식)

* WebSocket 대신 초기 구현 복잡도를 낮춘 Polling 방식 채택

1. 프론트엔드에서 PeerJS로 발급받은 `peerId`를 백엔드에 등록
2. 프론트엔드는 3초마다 상대방 입장 여부 조회
3. 면접관/지원자 `peerId`가 모두 등록되면 상대방 ID 반환
4. 프론트엔드에서 `peer.call()` 실행 → P2P 연결 성립

#### 자동화 로직 (Scheduler)

* 면접 예약 시간 기준으로 방 상태 관리
* 상태 흐름: `WAITING → OPEN → CLOSED`
* 면접 시작 10분 전 자동 OPEN
* 종료 후 일정 시간 경과 시 방 데이터 자동 정리

---

### 구현 포인트

* InterviewRoom Entity에 시작 시간(startTime)과 상태(status) 포함
* `@Scheduled`를 활용한 자동 오픈 로직 구현
* 상대방 미입장 시 `{ "partnerId": null }` 반환으로
  프론트엔드 조건 분기 단순화

---

### 트러블 슈팅

**문제 1) Repository 메서드 누락**

* cleanup 로직 구현 중 컴파일 에러 발생
* 원인: Service에서 호출한 메서드가 Repository에 정의되지 않음
* 해결: JpaRepository에 메서드 선언 + `@Transactional`, `@Modifying` 추가

**문제 2) Partner ID 응답 형식**

* 상대방이 없을 때 응답 정의가 모호했음
* 해결: 명시적으로 `null` 반환
* 프론트에서는 `if (res.data.partnerId)`로 깔끔한 분기 가능

## 🧠 오늘의 배운 점

* PeerJS는 연결만 담당하고,
  **방 관리·매칭·타이밍 제어는 백엔드의 역할**이다
* 프롬프트에서 추출 범위와 우선순위를 명확히 정의하지 않으면
  누락과 과잉 추출이 동시에 발생할 수 있다
* Polling 방식은 단순하지만
  초기 구현 및 디버깅 단계에서는 충분히 실용적인 선택이 될 수 있다
* 프론트, 백엔드, AI 분석 로직은
  결국 하나의 사용자 경험으로 연결되어야 한다
