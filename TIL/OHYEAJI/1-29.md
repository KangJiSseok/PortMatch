# 2026.01.29 TIL

## 📌 배경

* OpenVidu 2.30 기반 환경

  * `openvidu-browser 2.30`
  * `openvidu-java-client 2.30`
* 프론트 / 백엔드 / 인프라가 모두 준비된 상태였지만
  **WebRTC 연결이 지속적으로 실패**하는 문제가 발생함
* 초기에는 토큰 문제로 의심했으나, 최종적으로는 **SSL 인증서 문제**로 원인이 정리됨

---

## ❗ Problem (증상)

* OpenVidu **토큰 발급은 정상**
* 하지만 세션 연결 단계에서 실패

  * `invalid token (401)`
  * `wss` WebSocket 연결 실패
  * 브라우저 에러: `NET::ERR_CERT_AUTHORITY_INVALID`
* 결과적으로 영상/음성 연결 불가

---

## 🔍 Cause (원인 분석)

### 1) 토큰 자체는 문제가 아님

* 토큰 문자열을 조금이라도 수정하면 즉시 `401 invalid token`
* 토큰을 그대로 사용하면 인증 단계까지는 정상 진행됨
* 즉, **토큰 발급 로직은 정상**

### 2) 핵심 원인: 인증서(SSL) 문제

* OpenVidu 로그에서 반복적으로 확인된 메시지:

  * `openvidu-selfsigned.p12`
* 의미

  * `CERTIFICATE_TYPE=owncert` 설정에도 불구하고
  * OpenVidu가 **owncert를 읽지 못하고 self‑signed 인증서로 fallback**
* 결과

  * 브라우저가 `wss://도메인:8443` 인증서를 신뢰하지 못함
  * WebSocket 단계에서 연결 차단

---

## 🔧 Solution Attempt (해결 시도 흐름)

### 1) KMS(Kurento) 부재 문제 해결

* OpenVidu Server 단독 실행 시 세션 생성 실패
* 해결

  * `kurento-media-server` 컨테이너 추가
  * 설정

    ```yaml
    KMS_URIS=["ws://kurento:8888/kurento"]
    ```
* 로그에서 `OpenVidu Server using one KMS` 확인

---

### 2) HTTPS / WSS 구조 정리

* OpenVidu HTTPS 포트 `8443`으로 통일
* 토큰이 `wss://도메인:8443?...` 형태로 발급되는 상태 확보
* 설정 예시

  ```yaml
  OPENVIDU_HTTPS_PORT=8443
  HTTPS_PORT=8443
  OPENVIDU_URL=https://openvidu-server:8443/
  ```

---

### 3) owncert 적용 시도

* `CERTIFICATE_TYPE=owncert` 설정
* 인증서 파일 요구 사항 확인

  * `certificate.cert`
  * `certificate.key`
* 시도한 방법

  * 인증서 파일 복사
  * 심볼릭 링크 연결
  * entrypoint에서 `/opt/openvidu/owncert`로 매핑
* 결과

  * 여전히 **self‑signed fallback** 발생
  * 로그에서 self‑signed keystore 사용 지속 확인

---

### 4) 인증서 상태 확인 방법

* 로그 기반 확인이 필수

  ```bash
  docker logs openvidu-server --tail 200 | egrep -i "selfsigned|certificate|keystore|p12"
  ```
* 브라우저에서 `https://도메인:8443` 접속 시

  * 인증서 오류가 발생하면 owncert 미적용 상태로 판단 가능

---

## 📌 Result (현재 상태)

* OpenVidu 서버는 `8443 HTTPS`로 **정상 기동**
* 토큰은 `wss://도메인:8443?...` 형태로 **정상 발급**
* 그러나

  * 브라우저 인증서 오류(`ERR_CERT_AUTHORITY_INVALID`)로 인해
  * WebSocket 연결 실패
* **핵심 미해결 과제**

  * owncert를 OpenVidu에 정상적으로 적용시키는 것

---

## 🧠 Lesson Learned (배운 점)

* OpenVidu 2.30은

  * owncert 적용 실패 시 **조용히 self‑signed로 fallback**됨
* 토큰이 `wss`로 발급되더라도

  * 인증서가 신뢰되지 않으면 WebSocket 연결은 실패함
* 인증서 문제는

  * 프론트 코드가 아니라 **로그**로 판단해야 함
* 프록시(Nginx)와 직접 접속 구조가 섞이면

  * 토큰 발급 포트 / 실제 접속 포트 불일치로 `401`이 발생할 수 있음
* LiveKit 기반 OpenVidu 3.5 스택은

  * 구조가 완전히 달라 **사실상 재개발 수준의 전환 비용**이 필요함

---

## ✍️ 정리

이번 이슈의 본질은 **WebRTC나 토큰이 아니라 SSL 인증서**였다.
OpenVidu 2.x 환경에서 인증서 적용은 매우 까다롭고,
실패 시 명확한 에러 없이 self‑signed로 fallback되기 때문에
로그 기반 분석이 필수라는 점을 체감한 하루였다.
