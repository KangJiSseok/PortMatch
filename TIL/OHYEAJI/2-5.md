## 1️⃣ 지원자 목록 페이지 – 면접 일정 버튼 상태 오류 수정

### 문제

* 지원자 목록(Applicant List)에서
  이미 면접 일정이 잡힌 지원자임에도 불구하고
  항상 **“면접 일정 등록” 버튼**이 노출됨
* 원인은 로컬 캐시(`getExtraInterviewViews`) 기준으로만 상태를 판단했기 때문
* 실제 백엔드 연동 환경에서는 해당 캐시가 비어 있어 잘못된 UI 표시 발생

### 해결

* `JobApplicationManagementPage.tsx` 수정
* 특정 공고(jobPostId)에 대한 **실제 면접 데이터**를 백엔드에서 조회하도록 변경

  * `fetchInterviewRowsByJobPostId` API 사용
* 조회한 면접 데이터를
  `userId → interviewId` 형태의 Map(`existingInterviews`)으로 관리
* 지원자 목록 렌더링 시

  * 기존 로컬 데이터가 아닌 **실제 면접 존재 여부**를 기준으로 버튼 상태 분기

### 결과

* 면접 일정이 이미 있는 지원자:

  * 버튼 텍스트 → **“일정 수정”**
  * 클릭 시 스케줄 페이지가 수정 모드로 진입
* 면접 일정이 없는 지원자:

  * 기존처럼 일정 생성 플로우 유지
* 실제 서비스 데이터 기준으로 UI와 동작이 일치하게 됨

## 2️⃣ 면접 로비 – “유효하지 않은 면접” 오류 해결

### 문제

* 면접 목록에서 로비로 진입 시
  **“유효하지 않은 면접입니다”** 오류 발생
* 데이터 로딩 실패로 로비 진입 불가

### 원인

* 역할(role) 값 불일치

  * localStorage: `corporate`
  * 서버 API 기준: `COMPANY`
* 프론트에서 잘못된 역할로 API를 호출하면서
  서버가 사용자를 기업 회원이 아닌 것으로 판단

### 해결

* 역할 판별 기준을

  * localStorage 직접 참조 → `useAuthStore` 중앙 상태 기준으로 변경
* 프로젝트 전반에서 사용하는 표준 역할 값(`COMPANY`)에 맞춰 로직 통일

### 결과

* 올바른 API 호출 보장
* 면접 로비 정상 진입 가능

## 3️⃣ 화상 면접 페이지 – 미디어 스트림 안정화

### 문제 1) 마이크를 끄면 카메라 화면까지 꺼지거나 깜박임

### 문제 2) 상대방 입장 확인을 위한 3초 폴링 시 화면이 끊김

### 원인

* 마이크 상태 변경 시 카메라 초기화 로직까지 함께 실행됨
* 폴링마다 기존 미디어 연결을 정리(cleanup)하면서 스트림이 끊김

### 해결

* **의존성 분리**

  * 마이크 / 카메라 상태 변화를 각각 독립적으로 관리
* **스트림 유지 전략 적용**

  * 폴링 시에는 미디어 연결을 재설정하지 않고 상태만 확인
* **연결 순서 개선**

  * 상대방 peerId 확인 이후에만 실제 미디어 연결 시도

### 결과

* 대기 중 화면 깜박임 완전 제거
* 마이크 ON/OFF 시 카메라 영향 없음
* 화상 면접 UX가 안정적으로 개선됨

## 4️⃣ 백엔드 – 면접 방 자동 OPEN 로직 개선

### 문제

* 면접 시작 시간이 임박한 상태에서 방을 생성했음에도
  스케줄러가 실행되기 전까지 방 상태가 `WAITING`에 머무름
* 이로 인해 면접관/지원자 입장이 지연됨

### 해결

* 방 생성(`createRoom`) 시점에

  * 현재 시간이 면접 시작 **10분 전 이내인지** 확인하는 로직 추가
* 조건을 만족하면 생성 즉시 방 상태를 `OPEN`으로 설정

### 결과

* 면접 직전 생성된 방도 즉시 입장 가능
* 스케줄러 주기에 의존하지 않는 안정적인 동작 확보

* 로컬 캐시 기반 UI는 실제 백엔드 연동 시 쉽게 깨질 수 있으며,

* 기능 추가만큼이나
  **불필요한 코드 제거와 구조 정리**도 서비스 안정성에 큰 영향을 준다
