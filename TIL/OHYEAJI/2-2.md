## 1️⃣ 역할(Role) 기반 면접 UI 분기

### 문제

* 개인 사용자와 기업 사용자가 동일한 면접 UI를 공유
* 버튼, 기능 노출이 섞이면서 UX 혼란 발생
* 실제 면접 플로우(질문 주도 주체, 종료 권한 등)가 역할에 따라 달라야 했음

### 해결

* `InterviewPage`에서 로그인 사용자 `role` 기준 UI 분기 적용
* 기업 / 개인 사용자에 따라 다음 요소 분리

  * 제어 버튼 노출 여부
  * 질문/메모 관련 UI 권한
* 조건부 렌더링 구조 정리로 추후 역할 추가에도 대응 가능하도록 개선

### 결과

* 면접 화면의 책임 주체가 명확해짐
* 실제 서비스 흐름에 맞는 UI 구조 확보

## 2️⃣ 면접 메모 API 연동

### 문제

* 면접 메모가 프론트 상태로만 존재
* 새로고침 시 메모 유실
* 실제 면접 기록으로 활용 불가

### 해결

* 메모 조회 / 저장 API 연동
* 면접 질문 단위로 메모를 불러오고 수정 가능하도록 구현
* 면접 중 실시간 기록 → 서버 저장 구조 완성

### 결과

* 면접 종료 후에도 기록 유지 가능
* 면접 데이터의 활용 가치 증가 (리뷰, 피드백 등)

## 3️⃣ Interview 페이지 UI 리팩터링

### 문제

* 로비 / 면접 페이지 UI 구조가 복잡
* 상태 관리와 UI가 강하게 결합됨

### 해결

* 로비 페이지와 실제 면접 페이지 UI 구조 분리
* 불필요한 컴포넌트/상태 제거
* 사용자 흐름 기준으로 UI 재정렬

### 배운 점

* 실시간 기능이 있는 페이지일수록
  **역할·상태·UI 책임 분리가 중요**하다는 것을 체감함
