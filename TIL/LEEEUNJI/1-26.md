## 1. CI는 로컬과 다른 ‘완전히 깨끗한 환경’이다  

로컬에서 통과하던 코드가 CI에서만 터지는 이유는  
CI가 **캐시 없는 새 환경**에서 실행되기 때문이다.

- 로컬
  - 캐시 존재
  - node_modules 누적
  - 타입 꼬여도 실행 가능
- CI
  - 매번 새 컨테이너
  - ❌ 숨겨진 타입 에러 전부 노출

### 실제 문제 포인트
- import 대소문자 불일치  
  (`States` ↔ `states`)
- localStorage 타입 단언 (`as`)
- optional 값 처리 미흡 (`job.image`)

> CI 에러는 새로 생긴 문제가 아니라  
> 로컬이 관대했던 결과였다.

---

## 2. CI 에러를 막는 유일한 방법은 로컬에서 먼저 터지게 하는 것이다  
CI에서 안 터지게 하려면  
로컬에서도 CI와 동일한 검사 수준을 유지해야 했다.

```bash
npm run build
# 또는
npx tsc --noEmit
```
여기서 터지면 CI에서도 100% 터진다.

## 3. CTA는 버튼이 아니라 ‘사용자 행동 설계’다

CTA는 단순한 버튼이 아니라 이 화면에서 사용자가 반드시 해야 할 행동이다.
- 메인 페이지: 로그인하고 분석 시작하기
- 추천 기업: 채용건수 클릭 → 공고 검색 이동
- 공고 0건 상태: 다시 검색하기

> CTA는 명확해야 한다 (페이지당 핵심 CTA는 보통 1개)

## 4. UI 통일감은 디자인이 아니라 구조에서 나온다
UI가 안정적으로 보이기 시작한 이유는
색이나 컴포넌트가 아니라 구조를 통일했기 때문이었다.
- 페이지 폭 통일
- 헤더 / 섹션 시작 위치 정렬
- 조건부 렌더링에서도 레이아웃 크기 고정
- 0건 상태는 실패 화면이 아니라 다음 행동 안내 화면
> 내용만 바꾸고, 틀은 유지한다.

## 5. 접근성은 선택이 아니라 기본값이다
- 클릭 차단 vs 비활성 스타일 구분
- aria-disabled, cursor 처리
> 사용자에게 “왜 안 되는지”를 보여주는 UI
