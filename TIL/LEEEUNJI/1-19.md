## 1. Tailwind v4에서 색상 토큰이 바로 적용되지 않았던 이유

### 문제 상황

- `bg-cloud-dancer`, `text-midnight-ink` 같은 클래스가 적용되긴 했지만  
  왜 이렇게 동작하는지 이해가 안 됨
- `tailwind.config.js`가 없어서 설정이 깨진 줄 알았음
- CSS에 `@theme`를 사용하자 IDE에서  
  `Unknown at rule @theme` 경고 발생

### 원인 정리

- 현재 프로젝트는 **Tailwind v4 방식**
- v4에서는:
  - `tailwind.config.js` 없이도
  - **CSS 파일 안에서 `@theme`으로 토큰 정의 가능**
- IDE 경고는:
  - 에디터가 v4 문법을 완전히 인식 못해서 발생
  - ❗ **실제 빌드/런타임에는 영향 없음**

### 배운 점

- **경고 ≠ 에러**
- Tailwind v4에서는  
  👉 **CSS 자체가 설정 파일 역할을 한다**

> **한 줄 정리**: Tailwind v4에서는 “CSS가 곧 설정이다.”

## 3. Tailwind 토큰을 쓰는 올바른 관점

### 잘못된 사용

```tsx
bg-[#f0eee9]
```

### 올바른 사용
```tsx
bg-cloud-dancer
text-midnight-ink
border-soft-pebble
```

### 이유
- 색은 디자인 결정 사항
- 컴포넌트에서는:
    - 색 값 ❌
    - 의미(역할) 만 드러나야 함
- background / text / border의 의도만 표현

> 핵심: 컴포넌트는 “무슨 색인가”가 아니라
> “왜 이 색인가”를 드러내야 한다.

## 4. Git rebase 충돌에서 헷갈렸던 지점 정리
### 가장 큰 착각
- Current = 내가 쓰던 코드
- Incoming = dev에서 받은 코드

### 실제 의미 (rebase 중)
- HEAD(Current): 기준 브랜치 (보통 dev)
- Incoming: 지금 다시 얹고 있는 내 커밋
→ 그래서 Incoming에 내 코드가 보이는 게 정상

### 실전 교훈
- rebase 중에는 git pull ❌
- 충돌 해결 흐름은 항상:
```csharp
파일 수정 → git add → git rebase --continue
```

> 한 줄 정리: rebase 충돌은 “내 커밋을 dev 위에 다시 얹는 과정”이다.

## 5. API 연동 전에 타입 정의를 먼저 해야 하는 이유
### 왜 필요한가?
- API 응답 구조를 미리 계약해두기 위함
- 실제 효과:
    - 키 이름 틀리면 바로 에러
    - nullable 처리 누락 즉시 발견
    - 런타임 에러를 컴파일 단계에서 차단

### 깨달은 점
- 타입 정의는 나중 작업이 아니라
- API 연동을 쉽게 만들기 위한 준비 단계

> 타입은 “귀찮은 것”이 아니라
프론트엔드의 안전장치다.
