## 1️. AI 추천 카드 UI에서 ‘입체감’을 설계하는 법


#### 카드 Hover 전략
- 과한 흔들림, 틸트, 바운스 애니메이션 제거
- **Lift + Soft Glow**만 사용

#### **선택 이유**
- 카드 자체에 flip / modal이라는 강한 인터랙션이 이미 존재
- hover까지 복잡하면 UX 피로도 급증
- 커리어·리포트 성격 서비스에서는 **안정감 + 고급스러움**이 최우선

#### **적용 방식**
- hover 시 살짝 위로 이동(-translate-y)
- point-blue 기반의 은은한 shadow(glow)
- 내부 콘텐츠는 흔들리지 않게 고정

> 결과적으로 “AI가 선택한 카드”라는 인상만 강조되고 읽기 집중은 깨지지 않음

## 2. 컬러는 ‘행동’과 ‘구조’에만 사용한다

#### 컬러 사용 원칙
포인트 컬러는 **눈길을 끄는 장식이 아니라, 행동 안내용**

#### **point-blue (#5151E7) 사용처**
- 페이지 헤더의 구조 강조 요소
- CTA 버튼 (모집 공고 보기 / 합격 전략 리포트)

- 본문 텍스트

> 사용자 입장에서는 학습 없이도  
**“파란색 = 지금 눌러도 되는 곳”**으로 인식

## 3. 카드 인터랙션 우선순위 정리
이번 구현을 통해 카드 인터랙션의 기준을 명확히 정리했다.
#### 카드 인터렉션이란
- UI요소가 사용자의 행동(마우스, 키보드, 터치)에 반응하는 모든 방식

#### 인터렉션의 기준
1. 정보 구조가 먼저 (기업명 → 점수 → 근거)
2. Hover는 ‘암시’만 (Lift + Glow)
3. Click은 명확하게 (Flip / Modal)
4. CTA는 손맛이 핵심 (Press)

> 이 순서를 지키면 UI가 복잡해져도 사용자는 헷갈리지 않는다.

## 4. RecommendCompanyPage 모달 디버깅 핵심 정리

#### 1. import는 무조건 파일 최상단
- ES Module 규칙상 import는 파일 중간에 오면 즉시 에러
- 한 파일 = import는 한 덩어리, 맨 위에서만

#### 2. Fragment는 필요할 때만
- 불필요한 `<React.Fragment>`는
  오히려 React 식별자 충돌 원인이 될 수 있음
- 텍스트 조합은 그냥 `span`이 더 안전

#### 3. 모달이 안 뜰 때 가장 흔한 원인
- `open` 과 `company` 조건을 따로 체크하면서 타이밍 꼬임
- 해결: **렌더 조건을 하나로 통합** 
```ts
const visible = open && !!company;
if (!visible) return null;
```

#### 4. 모달 열릴 때 body scroll lock은 필수
UX 관점에서 선택이 아니라 기본

#### 5. “{기업명}은/는” 문제
조사 로직을 만들기보다문장 구조 자체를 조사 없는 형태로 설계

#### 6. 디버깅 순서
`이벤트 → 상태 → 렌더 → 스타일` 이 순서로 보면 대부분 해결된다.

## 5. UI 미확정 상태에서 API를 요청하는 기준
“UI가 아직 확정되지 않았는데, 이 JSON으로 가도 될까?”에 대한 의문이 있었다. 결론은 **가능**

#### 기준
- API는 화면이 아니라 역할 기준으로 설계
- 요청용 / 응답용 JSON을 명확히 분리

#### 요청 API
- 기업이 어떤 인재를 찾는지 정의
- 검색 조건, 가중치, 필터 전달

#### 응답 API
- 카드 렌더링, 점수 정렬, 모달 표시용 데이터
- UI가 바뀌어도 의미가 유지되는 구조

>  UI는 조립물이고 API는 재료다.
