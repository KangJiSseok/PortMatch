## 1. 검색 결과 페이지 UI 구현 과정

### 페이지 역할 정의

- 검색 페이지는 **입력을 받는 역할**
- 검색 결과 페이지는 **조건을 전달받아 결과를 표현하는 역할**

### 기준으로 삼은 관점

- 검색 결과 페이지는 “폼 화면”이 아니다
- 이미 조건은 정해져 있고
- 결과를 **정리해서 보여주는 책임**만 가진다

> 검색은 입력이 아니라  
> **조건 전달 + 결과 페이지 구조**다.

## 4. TypeScript 에러가 발생한 이유

### 에러 내용
`Already included file name differs only in casing`


### 상황 정리

- 실제 폴더 경로:
  - `components/States/ErrorState.tsx`
- import 경로:
  - `components/states/ErrorState.tsx`

→ 폴더 이름의 **대소문자만 다른 상태**

### 원인

- Windows 파일 시스템:
  - 대소문자 구분 ❌
- TypeScript 컴파일러:
  - import 경로 casing 엄격히 검사 ⭕

> OS는 괜찮아 보여도  
> TypeScript는 “다르다”고 판단한다.

## 5. 폴더 이름을 바꿨는데 git status에 안 잡힌 이유

### 헷갈렸던 부분

- `States → states`로 변경했지만
- git status에 변경 사항이 나타나지 않음

### 이유

- Git은 **폴더 자체를 추적하지 않음**
- 폴더 안 파일만 추적
- 해당 폴더에는 `.gitkeep`만 존재
- Windows에서는 대소문자 변경을 변경으로 인식하지 않음

→ Git 입장에서는 “변경 없음”

---

## 6. `.gitkeep`의 역할과 한계

### `.gitkeep`이란?

- Git이 빈 폴더를 추적하지 않기 때문에
- 구조 유지를 위해 넣는 **관례용 파일**
- Git의 공식 기능은 아님

### 오해했던 점

- `.gitkeep`이 있으면
  → 폴더 rename도 추적될 줄 알았음 ❌
- 파일 경로나 내용 변경이 없으면
  → Git은 변경으로 보지 않음

---

## 7. Git rebase & 잘못된 커밋 정리
### 상황
- dev 브랜치에서 잘못된 커밋 생성
- 아직 remote로 push하지 않은 상태

### 정리 방법
- 커밋 + 변경 내용 모두 삭제
`git reset --hard HEAD~1`

- 커밋만 취소하고 수정
`git reset --soft HEAD~1`
