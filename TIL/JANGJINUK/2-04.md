## 📅 TIL (Today I Learned) - 2026.02.04 (수)

### 1. 오늘의 목표

- 기업용 지원자 관리(ATS) 시스템 구축 및 실시간 메신저(Messenger) 기능 연동

---

### 2. 진행 내용

- **지원자 관리 API 고도화 연동**
  - **목록 및 상세 조회**: 특정 공고(`jobPostId`)에 대한 지원자 리스트를 불러오고, 개별 이력서의 상세 데이터(경력, 학력, 자기소개서, 포트폴리오)를 모달 형태로 렌더링하는 로직 구현.
  - **열람 상태 동기화**: 이력서 모달 오픈 시 서버에 `PATCH` 요청을 보내 '미열람' 상태를 '열람'으로 즉시 업데이트하는 비즈니스 로직 완성.
  - **동적 정렬 시스템**: `useMemo`를 활용하여 최신순, 경력순, 이름순으로 지원자를 즉각 필터링하는 최적화된 정렬 기능 제공.

- **실시간 커뮤니케이션 모듈 통합**
  - **Messenger 연동**: `useMessenger` 커스텀 훅을 통해 지원자 리스트 및 상세 보기에서 즉시 1:1 채팅방을 생성하고 연결하는 `handleContactApplicant` 핸들러 구현.
  - **인터페이스 일관성**: 메신저 레이어가 모달보다 상위에 노출되도록 설계하여 사용자 흐름(Flow)이 끊기지 않도록 처리.

- **UX/UI 디테일 강화**
  - **데이터 매핑**: 서버의 영문 Enum 값(`FULL_TIME`, `BACHELOR` 등)을 사용자 친화적인 한글 명칭으로 변환하는 `MAP` 객체 및 날짜 포매터 적용.
  - **접근성 및 피드백**: Framer Motion을 이용한 부드러운 모달 트랜지션과 지원자 부재 시의 Empty State 처리.

---

### 3. 배운 점 (Insights)

- **사이드 이펙트 관리 (Cleanup)**
  - `useEffect` 내에서 `cancelled` 플래그를 사용하여 컴포넌트 언마운트 시 비동기 API 요청 결과가 상태에 반영되지 않도록 방지하는 안정적인 데이터 페칭 기법을 적용함.
- **상태 동기화의 중요성**
  - 리스트 상태(`applications`)와 상세 모달의 데이터가 서로 유기적으로 반응(열람 처리 등)하게 함으로써 클라이언트와 서버 간의 데이터 정합성을 유지하는 경험을 쌓음.
- **사용자 시나리오 기반 설계**
  - "지원자 확인 -> 이력서 검토 -> 메신저 컨택 -> 면접 일정 확정"으로 이어지는 기업 담당자의 업무 흐름을 코드 구조에 그대로 녹여내어 도메인 이해도를 높임.
