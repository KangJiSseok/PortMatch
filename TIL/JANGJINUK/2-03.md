## 📅 TIL (Today I Learned) - 2026.02.03 (화)

### 1. 오늘의 목표

- 기업 공고 관련 API 연동 및 권한(Authorization)에 따른 UI 리디자인 완료

---

### 2. 진행 내용

- **기업용 공고 관리 API 연동**
  - 채용 공고의 생성(POST), 수정(PATCH), 삭제(DELETE) API를 연동하여 데이터 영속성 확보.
  - 공고 상세 페이지 진입 시, 해당 공고의 작성자 정보를 확인하는 서버 로직과 동기화.
- **권한 기반 조건부 렌더링 (Conditional Rendering)**
  - **본인 기업일 경우**: '공고 수정', '삭제', '지원자 명단 보기' 버튼 활성화.
  - **타 기업일 경우**: 버튼을 숨기거나 접근 제한 처리하여 데이터 보안 강화.
  - **구직자일 경우**: '지원하기', '스크랩' 버튼 위주의 UI로 전환.
- **페이지 리디자인 (UI/UX 최적화)**
  - 기업 사용자가 공고를 관리하기 편하도록 대시보드 형태의 레이아웃 리팩터링.
  - 불필요한 요소를 제거하고 현재 사용자의 상태(Role)에 최적화된 액션 버튼 배치.

---

### 3. 배운 점 (Insights)

- **Authentication vs Authorization**
  - 단순히 '누구인지(인증)'를 아는 것을 넘어, '무엇을 할 수 있는지(인가)'를 결정하는 로직을 구현하며 실제 프로덕션 수준의 권한 제어 흐름을 학습함.
- **사용자 중심의 UI 설계**
  - 모든 기능을 다 보여주는 것이 아니라, 사용자의 역할과 상황에 필요한 버튼만 노출하는 것이 인지 부하를 줄이고 깔끔한 UX를 만든다는 점을 체감함.
- **API 설계의 정합성**
  - 프론트엔드에서의 버튼 숨기기뿐만 아니라, 실제 API 요청 시에도 서버에서 한 번 더 소유권 검증을 거쳐야 보안이 완성된다는 점을 다시 한번 상기함.

### 4. 다음 단계

- **알림 연동**: 본인 공고에 새로운 지원자가 발생했을 때 기업 사용자에게 실시간 알림을 보내는 기능 검토.
