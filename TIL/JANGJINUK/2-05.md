## 📅 TIL (Today I Learned) - 2026.02.05 (목)

### 1. 오늘의 목표

- 기업용 '미열람 이력서' 식별 기능 및 지원 접수 시 자동 알림 로직 구현

---

### 2. 진행 내용

- **미열람 이력서(Unread Resume) 트래킹 시스템**
  - **상태 관리 로직**: 지원 내역 데이터에 `isRead` (또는 `status: 'UNREAD'`) 플래그를 활용하여, 초기 상태를 정의하고 기업이 이력서 상세 모달을 열람하는 시점에 읽음 상태(`READ`)로 업데이트하는 API 트리거 연결.
  - **UI 시각화**: 기업 담당자가 검토하지 않은 지원자를 한눈에 파악할 수 있도록 리스트 내 'NEW' 배지(Badge) 또는 하이라이트 스타일링 적용.

- **지원 접수 자동 알림 트리거 (Notification Trigger)**
  - **이벤트 기반 알림 생성**: 지원자가 '지원하기' 액션을 수행하는 즉시 백엔드에서 해당 이벤트를 감지하여, 공고 작성자(기업)에게 알림 데이터를 전송하는 로직 구현.
  - **데이터 페이로드 설계**: 알림 객체에 `applicantId`, `jobPostId`, `timestamp` 등의 메타 데이터를 포함하여 추후 알림 클릭 시 해당 지원서로 바로 이동할 수 있는 구조 마련.

---

### 3. 배운 점 (Insights)

- **능동적인 UX 설계 (Push vs Pull)**
  - 사용자가 수동으로 지원자를 확인해야 했던 'Pull' 방식에서, 시스템이 중요 이벤트를 즉시 알려주는 'Push' 방식으로 전환하며 플랫폼의 반응성을 획기적으로 높임.
- **상태 동기화의 디테일**
  - '알림 수신' → '이력서 열람' → '읽음 처리' → '배지 제거'로 이어지는 일련의 데이터 흐름이 매끄럽게 연결되어야 사용자에게 완성된 경험을 줄 수 있음을 체감함.
