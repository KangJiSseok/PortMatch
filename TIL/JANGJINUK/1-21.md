## 📅 TIL (Today I Learned) - 2026.01.21 (수)

### 1. 오늘의 목표

- 로그인 페이지 백엔드 API 연동 및 고도화된 유효성 검사 구현

### 2. 진행 내용

- **React Query 기반 인증 로직 연동**
  - `useLogin` 커스텀 훅을 통해 서버와 통신하며 `isPending` 상태를 이용해 중복 요청 방지 및 로딩 UI를 제어함.
  - 로그인 성공/실패 시의 사이드 이펙트를 처리하고, `rememberMe` 옵션을 연동하여 자동 로그인 로직의 기반을 마련함.
- **사용자 경험(UX) 중심의 유효성 검사**
  - 프론트엔드 1차 검증: 이메일 형식(Regex) 및 필수값 누락 여부를 판단하여 즉각적인 피드백 제공.
  - **Shake Animation:** 에러 발생 시 Framer Motion을 활용해 해당 필드가 흔들리는 효과를 주어 시각적으로 강조함.
  - **Focus Management:** 에러가 발생한 첫 번째 필드에 `useRef`를 사용하여 자동으로 포커스를 이동시킴.
- **커스텀 에러 UI 설계**
  - `WarningBubble`: 입력 필드 하단에 풍선 도움말 형태의 경고 메시지를 띄워 레이아웃 깨짐 없이 에러를 안내함.
  - 서버 에러 핸들링: `axios.isAxiosError`를 통해 401(미인증) 에러와 기타 서버 에러를 구분하여 사용자에게 메시지 출력.

### 3. 배운 점 (Insights)

- **조건부 인터랙션의 효과**
  - 단순히 텍스트 에러를 보여주는 것보다 흔들림 효과(Shake)와 자동 포커싱을 결합했을 때 사용자가 수정해야 할 지점을 훨씬 직관적으로 인지함을 배움.
- **유연한 에러 처리 로직**
  - 클라이언트 단계의 'Validation'과 서버 단계의 'Authentication' 에러를 계층별로 관리하여 코드의 가독성을 높임.
- **컴포넌트 재사용성**
  - `UserRole` 타입을 활용해 개인과 기업 로그인을 하나의 페이지 안에서 탭 형태로 전환하며, 같은 로직을 공유하도록 효율적으로 설계함.

### 4. 다음 단계

- **인증 유지(Persistence):** 로그인 성공 후 받은 Access Token을 전역 상태나 쿠키에 저장하여 인가된 사용자만 접근 가능한 프라이빗 라우트 설정.
