### 2. 진행 내용
* **면접 관리 API 완벽 연동**
    * **일정 확정 로직**: 이전에 구현한 '스케줄링(Firebase)' 기능에서 확정된 시간 데이터를 백엔드 DB(PostgreSQL)의 `interviews` 테이블로 이관하는 API 연동 완료.
    * **상태 동기화**: 면접 일정이 잡히면 해당 지원서의 상태가 자동으로 '면접 예정'으로 변경되도록 트랜잭션 처리.

* **타임라인 기반 자동 알림 시스템 (Scheduled Notifications)**
    * **다중 알림 트리거**: 면접 시작 시간을 기준으로 **'1시간 전'**과 **'10분 전'**에 각각 리마인드 알림을 발송하는 스케줄러 로직 구현.
    * **목적별 메시징**: 1시간 전에는 "준비물 확인", 10분 전에는 "화상 회의실 입장 링크"를 포함하여 시점에 맞는 정보를 제공하도록 UX 설계.

* **프로젝트 전체 QA 및 폴리싱 (Polishing)**
    * **플로우 점검**: `공고 등록 -> 지원 -> 채팅 -> 일정 조율 -> 면접 확정 -> 알림`으로 이어지는 전체 채용 프로세스를 시뮬레이션하며 끊김 없는 연결 확인.
    * **완성도 보완**: UI 어긋남, 로딩 상태 처리 미흡 등 사용자 경험을 저해하는 요소들을 전반적으로 수정.

---

### 3. 배운 점 (Insights)
* **스케줄링 시스템의 정교함**
    * 단순히 데이터를 저장하는 것을 넘어, 시간(Time)을 트리거로 특정 동작(알림)을 수행하게 하는 백엔드 스케줄러(Scheduler)의 중요성과 구현 방식을 익힘.
* **사용자 행동 예측**
    * "사용자는 면접 시간을 깜빡할 수 있다"는 전제하에 이중 알림 장치를 마련함으로써, 서비스가 사용자를 케어한다는 느낌(Care UX)을 주는 방법을 배움.
* **통합 테스트의 가치**
    * 개별 기능이 잘 돌아가더라도, 전체를 연결했을 때 발생할 수 있는 데이터 정합성 문제나 UX 단절을 발견하고 해결하며 시스템의 견고함을 높임.
